## 4. 핵심 인사이트 (Top Lessons)

### L1. "read-only → 정밀 → 경고" progressive enhancement는 Epic 4/5/6의 좋은 패턴
- 3.1 stub → 3.2 정밀 → 3.3 경고 모두 **additive** — wire contract 호환
- 사용자 입력 흐름 무중단 + 회귀 위험 최소화
- **자산**: Epic 4 first_calc (`is_blocked` 직접 활용) + Epic 6 reporting warnings (Epic 3 warnings 재사용) + Epic 9 ABC allocation (read-only → 정밀)

### L2. "warning은 read-only" 패턴 (server-side defense)
- 3.3 AC #7: PATCH `warnings`/`is_blocked` → 400 INVALID_PAYLOAD (`extra='forbid'`)
- UI 단순 렌더 + `[마감]` enable/disable + server-side 강제
- **자산**: Epic 4 first_calc 응답의 `verdict` (PRD §F4.x) + Epic 5 ledger event `block_reason` 모두 같은 패턴

### L3. inline projection + TODO(epic-5) marker는 Epic 5 ledger fold-in의 한 줄 swap 진입점
- 3.3 `LEDGER_REFERENCE_QUERY_STUB` + `monthly_input_periods.opening_inventory` JSONB → Epic 5 5-1 (auto-carry) + 5-2 (append-only) 진입점
- Epic 5 spec 작성 시 inline projection → ledger migration path 명시
- **자산**: Epic 5 첫 스토리에서 "Epic 3 inline projection을 fold-in하는가? 아니면 별도 신규 path인가?" 결정 가능

### L4. capability × type matrix는 3개 epic 연속 자산, Epic 4에서도 표준
- Epic 1+2+3 모두 동일 패턴 (`Capability` enum + `_INDUSTRY_CAPABILITIES` + `tests/integration/test_capability_consistency.py`)
- Epic 4 (m3_calculate) + Epic 5 (m4_inventory) + Epic 9 (m9_abc) 진입 시 같은 체크리스트
