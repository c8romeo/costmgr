### W1. M0 ↔ M1 ↔ M9 ↔ M10 책임 분리 (AD-1 헥사고날 정착)
- Epic 1 종료 시점: 4 모듈 (m0_onboarding / m1_baseline / m9_abc / m10_ai) 별도 라우터 + 별도 service + port 경계 명확

- **자산**: Epic 3의 m2_input + Epic 4의 m3_calculate + Epic 5의 m4_inventory에 같은 패턴 즉시 적용 가능

### W2. A7 전진법 + 7일 grace window 일관 적용 (1-1 + 1-2)
- industry / fiscal_year_start / currency 모두 동일 패턴: `decision.allowed + is_initial + days_since < 7 → allowed`, else `IndustryLockedError` / `FiscalYearLockedError` / `CurrencyLockedError`
- `_days_between()` UTC calendar-day floor (F-26) — 시차/자정 boundary 안전
- **자산**: Epic 4 first_calc 이후 A7 lock이 모든 회계연도-관련 필드에 적용 가능 (lock 패턴은 Epic 1에서 검증 완료)

### W3. `compute_completion()` pure function + DraftSummary 통합 (1-2 → 1-3)
- Story 1.2의 `compute_completion(industry, onboarding, counts)` pure function이 Story 1.3의 `pending_extractions` 파라미터로 확장
- mock_session fallback으로 DB 없이도 테스트 가능 (Story 1.2 T4.2의 deferred-to-test-only 패턴)
- **자산**: Epic 3 (월 입력 + completion) + Epic 5 (재고 + completion)에서도 동일 pure-function + JSONB-aggregate 패턴

### W4. Audit-first + idempotent no-op (CR 1.1 lesson) Epic 1 정착
- 1-1 update_industry + 1-2 update_onboarding_field + 1-3 document upload 모두 동일 패턴:
  1. SELECT FOR UPDATE
  2. emit_audit() with `flush=True`
  3. UPDATE row
  4. settings_version + 1
- same-value POST는 audit skip + version no-op (CR 1.1 F-8/F-9)
- **자산**: Epic 2 Epic 2의 BOM/product writes에도 동일 패턴 전사 확산 (Epic 2 회고 W2)

### W5. AI Extraction port/adapter/handlers 구조 (1-3 backend)
- `packages/services/m10_ai/extraction_port.py` (stdlib-only) + `apps/api/modules/m10_ai/adapters/{fake_adapter,claude_vision}.py` + `service.py` + `handlers.py` 4-layer 구조
- FakeDocumentExtractionAdapter 결정성 (sha256-of-bytes seed + FAKEFAIL/FAKEZERO/FAKEFIELD magic bytes) — test 안정성
- `DocumentExtractionPort.extract()` 반환은 항상 `DocumentExtractionJob` (status 4-state FSM) — try/except in handlers 제거
- **자산**: Epic 3+에서 신규 adapter 추가 시 동일 패턴 적용 (예: Epic 10-3 reference vs auto-analysis 분리 시 port 확장)

### W6. PIPA gate defense-in-depth (1-3 §2.4 deviation)
- 스펙은 env-flag (`PIPA_REVIEW_COMPLETED`) 제안, 구현은 `tenant_settings.onboarding.pipa_consent + pipa_region` (KR-only) — **per-tenant** audit chain 가능
- `require_pipa_review` dependency로 first-line defense (body parse 이전 거부)
- deviation은 `docs/ai-document-extraction.md`에 명시
- **자산**: 운영자가 pilot 단계에서 tenant별 consent 부여 가능 (스펙 env-flag보다 세밀한 통제)
