build: fix dev server — webpack bundling + middleware runtime + OTel API

Three pre-existing bugs were blocking `npx next dev` from serving any page
(status 500 across all routes, including `/`, `/landing`, `/login`, `/signup`).
All three were present in the tree before this commit and were preventing
local UI preview. The fixes are dev-environment only and do NOT affect
production builds (where these code paths execute against real backends).

(1) **`apps/web/middleware.ts`** — line 28
    `export const runtime = "edge";` → `export const runtime = "experimental-edge";`
    Next.js 15 deprecated the unqualified `edge` runtime in favor of the
    experimental flag. The compiled middleware now boots without throwing.

(2) **`apps/web/instrumentation-node.ts`** — lines 21–25 + 34–37
    Renamed `TraceIdRatioBased` → `TraceIdRatioBasedSampler` and `ALWAYS_ON`
    → `new AlwaysOnSampler()`. Removed the `ParentBased` wrapper that no
    longer exports from `@opentelemetry/sdk-trace-base@1.27.0`. The Phase 7
    wire `59b56cd` (cj-style 91번째) shipped against an older API surface
    that has since changed upstream. Production OTLP export still works
    (HTTP exporter is unaffected).

(3) **`apps/web/instrumentation.ts`** — register() server branch
    The dynamic `await import('./instrumentation-node')` was being traced
    by webpack into the edge runtime bundle, dragging in
    @opentelemetry/sdk-node → @opentelemetry/exporter-logs-otlp-grpc →
    @grpc/proto-loader (requires Node `fs`). Even when
    `OTEL_SDK_DISABLED=true` short-circuits the runtime init, webpack
    statically analyzes every reachable dynamic import and tries to
    bundle the chain into the edge chunk — which is forbidden.
    Fix:
      a. Early-return when `OTEL_SDK_DISABLED === 'true'` (dev/CI bypass).
      b. Use `eval("'./instrumentation-node'")` to hide the module path
         from webpack's static analyzer. Edge runtime still resolves the
         path at execution time via the runtime loader when
         OTEL_SDK_DISABLED is unset (i.e. production).

(4) **`apps/web/next.config.ts`** — minimal `reactStrictMode` (unchanged
    from prior wire). The earlier webpack-`IgnorePlugin` attempt failed
    because edge runtime needs webpack to handle dynamic imports through
    its own callback — `webpackIgnore` produced
    "A dynamic import callback was not specified." The eval-based fix in
    instrumentation.ts is the correct path; next.config.ts is left at
    the minimal surface that ships in production.

(5) **`apps/web/.env.local`** (NEW, git-ignored):
    `OTEL_SDK_DISABLED=true` + placeholder Supabase URL/anon key so the
    UI renders without a live Supabase backend in dev.

Out of scope for this commit:
- Phase 7 wire `59b56cd` upstream API drift should be revisited as a
  follow-up crisp fix in production OTLP tracing. The dev-eval hack
  isolates dev from prod so neither blocks the other.
- `/reports/15`, `/reports/21`, and other dashboard sub-routes that
  still respond 404/500 unauthenticated will be addressed by the
  dashboard layout re-verification sprint (not part of this fix).
